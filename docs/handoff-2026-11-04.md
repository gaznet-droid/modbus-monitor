# Handoff: ModPi build and production move, 3–4 November 2026

Covers the Claude Code session that built the Raspberry Pi, moved production onto it,
simplified the Power tab and prepared for the move to Dad's house. Includes state that
exists only on the Pi or the Mac and is not in git. This repository is public: no
secrets, public IPs or internal addresses are recorded here, only where they live.

## Where things stand

- modbus.clockmillbarn.uk is served entirely by ModPi, a Raspberry Pi 3 Model A+ at
  Gareth's house on its own power supply, on the Clock Mill Barn Wi-Fi (Google Nest).
  The Mac, Slave and the RUTX12 play no part in Modbus any more.
- Meter, eWeLink and Tuya (Juwai) are all collecting and storing on the Pi's microSD.
- Remote maintenance is through Tailscale, so the Pi can be reached after it moves.
- The Pi is ready to move to Dad's house. The two jobs after the move are local meter
  reads and local Tuya reads (see Next steps).

## What was done

### 3 November
- Confirmed the board is a Raspberry Pi 3 Model A+ (512 MB RAM, Wi-Fi only, no Ethernet).
- The 32 GB PNY card held an old image that had already booted on another Pi and had
  no Wi-Fi country set. It was reflashed from Gareth's Terminal (Claude Code cannot
  write raw disks on macOS) with Raspberry Pi OS Lite 32-bit, Trixie, 2026-10-06,
  checksum verified.
- First-boot settings were supplied as cloud-init files: hostname modpi, user admin,
  SSH key only, passwordless sudo, Wi-Fi Clock Mill Barn with country GB,
  Europe/London, GB keyboard.
- OS fully upgraded. The modbus-pi checkout was installed with pi/install.sh and the
  57-test suite passed on the Pi.
- Fixed a startup crash: the storage guard checked that / was writable, but the
  service sandbox (ProtectSystem=strict) makes / read-only. It now checks the mount
  that holds the data directory.
- Added Dad's Wi-Fi as a second NetworkManager profile and stopped cloud-init from
  managing the network.
- Installed Tailscale on the Pi and on the Mac. The Mac runs macOS 12.7.6, so it has to
  stay on Tailscale 1.90.9: newer network extensions need macOS 13.5. Downgrading
  needed a clean remove and pkgutil --forget, because the installer kept the newer
  system extension.
- Pi Tailscale key expiry is disabled.
- A one-off read-only meter read from the Pi matched the Mac's live value. The meter
  address was taken from the running process, not by reading Slave.
- Branch raspberry-pi pushed to GitHub.

### 4 November
- Ported the Tuya collector to the Pi (pi/tuya_run.py, modpi-tuya.service, with no
  automatic restart by design). Added modpi-tunnel.service, which passes the tunnel
  token as a systemd credential. Installed cloudflared from Cloudflare's signed apt
  repository.
- Production cut-over, 09:12 to 09:15:
  - Gareth stopped the Mac supervisor himself, because the permission system blocks
    Claude from stopping production. Slave's supervisor.pid was stale; the real
    process ID was 70630.
  - The leftover setup_ewelink.py process was also stopped.
  - The three databases were copied with SQLite .backup and integrity-checked.
  - Copied to the Pi: the eWeLink private files (config, tokens, budget, schedule),
    the Tuya config and the tunnel token.
  - Collectors enabled, then the Tuya service, then the tunnel. Tuya and eWeLink each
    polled successfully from the Pi on their first cycle.
- Meter outage: readings stopped at 01:18. Dad's site lost internet briefly (all
  eWeLink devices went offline at 01:19) and came back with a new public IP. Gareth
  supplied the new address, it was set on the Pi, and readings resumed at 09:39. The gap from
  01:18 to 09:39 is permanent. Lesson: Tuya's device-info IP field was stale and
  misleading.
- Power tab: the voltage chart, the last-reading and updated lines, and the donut card
  were removed. Imported and exported now sit between the headline figures and the
  graph, and the time window menu is in the tab bar, top right. Deployed by replacing
  /opt/modpi/router/web/index.html only, because the server reads the page on each
  request, so nothing restarted.
- Tuya local keys and MAC addresses fetched for both Juwai CW20 meters, read-only,
  before the cloud trial ends on 23 November. They are stored on the Pi and on the Mac.

## Decisions
- The login user is admin. The app runs as the unprivileged modpi user.
- 32-bit OS, which suits 512 MB of RAM.
- Tailscale is used for maintenance, kept separate from the public Cloudflare tunnel,
  so a tunnel fault cannot lock us out.
- Production moved while the Pi was at Gareth's house. The move to Dad's comes later
  this week.
- The Tuya collector was ported rather than dropped, until local reads replace it.
- Live Net Power and the Combined Meter Reading always show current values. The time
  window drives the graph and the imported and exported totals.

## Blockers and risks
- The meter is still reached through Dad's dynamic public IP and a router port-forward.
  Any IP change stops readings until meter_host is updated. Exposing Modbus TCP to the
  internet is also a security risk, and this repository is public; an old public IP
  already appears in its early history.
- The Tuya cloud trial ends on 23 November. Local Juwai access is unproven, and the
  keys change if a meter is re-paired in Smart Life.
- The dad-bthub Wi-Fi profile is untested, and the Pi has no Ethernet. A wrong password
  means a site visit with a screen and keyboard.
- After the move, the meter's public IP may not work from inside Dad's own network if
  his router lacks NAT loopback. Expected fix: switch to the meter's LAN address.
- The meter has dropped out for 25 to 40 minutes most evenings, around 17:45 to 18:30,
  between 28 and 31 October, while eWeLink stayed online. This needs checking on site.
- Dad's Wi-Fi is a BT Hub, but the meter's public address is on TalkTalk. Confirm that
  they are the same connection when on site.
